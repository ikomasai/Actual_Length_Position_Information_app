# プロジェクト仕様書 - 位置情報オンデマンド取得アプリ

## プロジェクト概要

このプロジェクトは、ERPシステムからの呼び出しに応じてユーザーの位置情報を取得し、Supabaseに保存するiOS対応のモバイルアプリケーションです。
取得した位置情報は、ERPの実長タブでマップ表示されます。

### プロジェクト目的

- アプリをダウンロードしたユーザーの位置情報を取得
- ERPシステムからの呼び出しがあった時のみ位置情報を送信
- 取得した位置情報をSupabaseに保存
- ERPの実長タブでマップ表示して位置情報参照を可能にする

### 技術スタック

- **フロントエンド:** React Native (Expo)
- **バックエンド:** Supabase
- **位置情報取得:** expo-location
- **プッシュ通知:** expo-notifications（呼び出し受信用）
- **ストレージ:** @react-native-async-storage/async-storage
- **使用言語:** JavaScript（TypeScript ではない）
- **対応プラットフォーム:** iOS

## アプリケーション機能要件

### 1. 位置情報取得機能

#### 1.1 権限管理
- **位置情報権限**: アプリ使用中の位置情報取得
- **バックグラウンド位置情報権限**: 呼び出し受信時の位置情報取得用
- 権限リクエストダイアログの表示
- 権限が許可されない場合のエラーハンドリング

#### 1.2 位置情報取得設定
- **精度**: 高精度（GPS使用）
- **取得タイミング**: ERPからの呼び出し時のみ
- **バックグラウンド動作**: 呼び出し受信時にのみ実行

#### 1.3 取得する位置データ
- 緯度（latitude）
- 経度（longitude）
- 高度（altitude）
- 精度（accuracy）
- 速度（speed）
- 方向（heading）
- タイムスタンプ（timestamp）

### 2. ユーザー識別機能

#### 2.1 ユーザーID管理
- 初回起動時にユーザーIDの入力を求める
- ユーザーIDをローカルストレージに保存
- 位置情報とユーザーIDを紐付けて保存

### 3. ERP呼び出し受信機能

#### 3.1 呼び出し監視
- アプリ起動中は常に呼び出しを待機
- バックグラウンドでも呼び出しを受信可能（プッシュ通知）
- 呼び出し受信時に位置情報を自動取得・送信

#### 3.2 呼び出し方法
- Supabaseのリアルタイム機能を使用
- `location_requests`テーブルに新規レコード挿入で呼び出し
- アプリ側でテーブル変更を監視

#### 3.3 通知機能
- 呼び出し受信時に通知を表示
- 位置情報送信完了の通知

### 4. データ保存機能

#### 4.1 Supabase連携
- 呼び出し時に取得した位置情報をSupabaseに送信
- 送信履歴の保存
- 保存エラー時のリトライ処理

### 5. アプリ制御機能

#### 5.1 サービス開始・停止
- サービス開始ボタン（呼び出し待機開始）
- サービス停止ボタン（呼び出し待機停止）
- 現在の待機状態表示（待機中/停止中）

#### 5.2 ステータス表示
- 待機状態のビジュアル表示
- 最終送信時刻の表示
- 送信履歴の表示（直近5件程度）
- エラーメッセージの表示

## データベース設計

### Supabaseテーブル設計

#### locationsテーブル
位置情報を保存するメインテーブル

| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | uuid | PRIMARY KEY, DEFAULT uuid_generate_v4() | 自動生成ID |
| user_id | text | NOT NULL | ユーザー識別ID |
| latitude | double precision | NOT NULL | 緯度 |
| longitude | double precision | NOT NULL | 経度 |
| altitude | double precision | NULL | 高度（メートル） |
| accuracy | double precision | NULL | 位置精度（メートル） |
| speed | double precision | NULL | 速度（m/s） |
| heading | double precision | NULL | 方向（度） |
| timestamp | timestamptz | NOT NULL | 位置情報取得日時 |
| created_at | timestamptz | DEFAULT now() | レコード作成日時 |
| request_id | uuid | NULL | 呼び出しリクエストID（紐付け用） |

#### location_requestsテーブル
ERPからの位置情報取得リクエストを管理

| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | uuid | PRIMARY KEY, DEFAULT uuid_generate_v4() | 自動生成ID |
| user_id | text | NOT NULL | 対象ユーザーID |
| requested_at | timestamptz | DEFAULT now() | リクエスト日時 |
| completed | boolean | DEFAULT false | 完了フラグ |
| completed_at | timestamptz | NULL | 完了日時 |

#### インデックス
- `locations.user_id` にインデックス（検索性能向上）
- `locations.timestamp` にインデックス（時系列検索用）
- `locations.user_id, timestamp` の複合インデックス
- `location_requests.user_id` にインデックス
- `location_requests.completed` にインデックス

#### RLSポリシー（Row Level Security）
- INSERT: 認証不要（匿名での位置情報登録を許可）
- SELECT: ERP側のサービスロールキーでのみアクセス可能

## API 設計

### Supabase API

#### 位置情報登録API
- **テーブル**: `locations`
- **操作**: INSERT
- **エンドポイント**: Supabase REST API (自動生成)
- **リクエストデータ**:
  ```json
  {
    "user_id": "string",
    "latitude": number,
    "longitude": number,
    "altitude": number | null,
    "accuracy": number | null,
    "speed": number | null,
    "heading": number | null,
    "timestamp": "ISO8601 timestamp",
    "request_id": "uuid" | null
  }
  ```

#### 呼び出しリクエスト監視
- **テーブル**: `location_requests`
- **操作**: SUBSCRIBE (Realtime)
- **監視条件**: `user_id = [ログインユーザーID] AND completed = false`

## ERPシステム側の仕様

### 実長タブの機能

#### 位置情報呼び出しボタン
- ボタン配置: 実長タブ内の適切な位置

- 動作:

- Google Maps または Leaflet を使用
- ユーザーの現在位置をピン表示
- 住所情報の逆ジオコーディング表示
- 位置情報の取得日時を表示

## セットアップ手順

### 1. リポジトリのクローン
```bash
git clone [repository-url]
cd Actual_Length_Position_Information_app
```

### 2. 依存関係のインストール
```bash
npm install
```

必要なパッケージ:
- expo-location
- expo-notifications
- @react-native-async-storage/async-storage
- @supabase/supabase-js
- @react-navigation/native
- @react-navigation/native-stack

### 3. Supabaseプロジェクトの設定

#### 3.1 Supabaseプロジェクト作成
1. https://supabase.com でプロジェクトを作成
2. プロジェクトURLとAnon Keyを取得

#### 3.2 データベーステーブル作成
SQLエディタで以下を実行:

```sql
-- locations テーブル作成
CREATE TABLE locations (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id TEXT NOT NULL,
  latitude DOUBLE PRECISION NOT NULL,
  longitude DOUBLE PRECISION NOT NULL,
  altitude DOUBLE PRECISION,
  accuracy DOUBLE PRECISION,
  speed DOUBLE PRECISION,
  heading DOUBLE PRECISION,
  timestamp TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now(),
  request_id UUID
);

-- location_requests テーブル作成
CREATE TABLE location_requests (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id TEXT NOT NULL,
  requested_at TIMESTAMPTZ DEFAULT now(),
  completed BOOLEAN DEFAULT false,
  completed_at TIMESTAMPTZ
);

-- インデックス作成
CREATE INDEX idx_locations_user_id ON locations(user_id);
CREATE INDEX idx_locations_timestamp ON locations(timestamp);
CREATE INDEX idx_locations_user_timestamp ON locations(user_id, timestamp);
CREATE INDEX idx_location_requests_user_id ON location_requests(user_id);
CREATE INDEX idx_location_requests_completed ON location_requests(completed);

-- RLSポリシー設定
ALTER TABLE locations ENABLE ROW LEVEL SECURITY;
ALTER TABLE location_requests ENABLE ROW LEVEL SECURITY;

-- locations: INSERT許可（匿名アクセス可能）
CREATE POLICY "Allow anonymous insert" ON locations
  FOR INSERT
  WITH CHECK (true);

-- locations: SELECT許可（認証済みユーザーのみ）
CREATE POLICY "Allow authenticated select" ON locations
  FOR SELECT
  USING (auth.role() = 'authenticated');

-- location_requests: SELECT許可（匿名アクセス可能、自分のリクエストのみ）
CREATE POLICY "Allow user select own requests" ON location_requests
  FOR SELECT
  USING (true);

-- location_requests: INSERT許可（認証済みユーザーのみ）
CREATE POLICY "Allow authenticated insert" ON location_requests
  FOR INSERT
  WITH CHECK (auth.role() = 'authenticated');

-- location_requests: UPDATE許可（匿名アクセス可能、完了フラグ更新用）
CREATE POLICY "Allow update completed" ON location_requests
  FOR UPDATE
  USING (true)
  WITH CHECK (true);

-- Realtimeを有効化
ALTER PUBLICATION supabase_realtime ADD TABLE location_requests;
```

### 4. 環境変数の設定
```bash
cp .env.example .env
```

`.env` ファイルを編集:
```
EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 5. アプリを起動
```bash
npm start
```

### 6. iOS実機でのテスト
```bash
npm run ios
```

## 使い方

### アプリ側
1. アプリを起動
2. ユーザーIDを入力（初回のみ）
3. 「サービス開始」ボタンをタップ
4. 位置情報の権限を許可
5. アプリがバックグラウンドでも呼び出しを待機

### ERP側
1. 実長タブを開く
2. 「現在位置を取得」ボタンをクリック
3. アプリから位置情報が送信される
4. マップに位置情報が表示される

## 非機能要件

### パフォーマンス
- 呼び出し受信から位置情報送信まで: 10秒以内
- 位置情報の精度: 10m以内

### セキュリティ
- 位置情報は暗号化された通信で送信（HTTPS）
- Supabase RLSでアクセス制御
- ユーザーIDは識別用途のみ

### バッテリー消費
- 常時追跡ではないためバッテリー消費は最小限
- 呼び出し時のみGPSを使用
